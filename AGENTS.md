# Project Conventions

Rules for anyone who changes this repo, people and coding agents alike. `CLAUDE.md` imports this file.

## Writing

- Never use emdashes (—) or emojis anywhere: not in UI copy, code, comments, or generated strings.
- New functions and components get a short TSDoc comment: a one-sentence summary, then any why notes, with no step list. A function with several steps marks each step with a short comment inside the function, at the point where that step happens: `// Step 1: ...`, nested `// Step 2.1: ...`. Keep a step comment to one line where you can, never more than two `//` lines. When a step needs more, split it into sub-steps at the points in the code where each part happens (`// Step 1.1: ...`, `// Step 1.2: ...`) rather than write a long comment. Non-obvious constants get a one-line doc comment. Keep comments short; say why, not what.
- TSDoc uses only the standard tags, in this order: the one-sentence summary line, `@remarks` (longer why notes, measured numbers, caveats), `@param name - ...` for each parameter, `@returns` for a returned value, `@throws` when a function throws on purpose, `@typeParam T - ...` for each generic, `@defaultValue` for an optional value with a default, `@see` (the source of a rule or a value, or a related function), and `{@link name}` inline where a comment names another symbol. No types in braces (TSDoc takes them from the signature). Add a tag only where it adds a fact. Give the unit or the allowed values when the type does not show them. A component documents each prop with a one-line doc on the prop in its props type, not with `@param`.

## Git

- Commits are signed via SSH (`gpg.format=ssh`), not GPG - running `git commit` in a shell command is fine.
- Never add `Co-Authored-By` or `Claude-Session` footers to commit messages.
- Large changes land as multiple small, logically grouped Conventional Commits, not one big commit.
- Pull requests: a short body in ASD-STE100 (what changed, why, how to test), with no attribution or "generated with" lines. Show a UI change with images or a video uploaded to GitHub's attachment store, never committed (do not commit `.github/pr-assets`):
  1. Record the proof with synthetic data (`/test.html`) and the UTC time zone (Playwright `timezoneId: "UTC"`), never a real export or the computer's zone. Convert a Playwright webm first: `ffmpeg -i in.webm -c:v libx264 -pix_fmt yuv420p out.mp4`.
  2. Upload each file: `curl -s "https://uploads.github.com/user-attachments/assets?name=<file>&content_type=<mime>&repository_id=<id>" -X POST -H "Authorization: Bearer $(gh auth token)" -H "Accept: application/json" --data-binary @<file>` (`<id>` is `gh api repos/<owner>/<repo> --jq .id`; video types `video/mp4` or `video/webm`). A 422 means the type is not allowed; a 404, a wrong repository id or no push access.
  3. Put the returned `url` in the body: an image as `![what it shows](url)`, a video as the bare URL on its own line (GitHub shows a player; image syntax does not).

## Toolchain

- Use `bun --bun` for all script execution (`bun --bun dev`, `bun --bun test`). Use `bun add`/`bun remove` for package management. Never use Node, npm or Vite. Exception: `build` collides with Bun's own bundler subcommand, so `bun --bun build` runs _that_ and fails with "Missing entrypoints" - use `bun --bun run build` to run `scripts/build.ts`.
- Use `bunx --bun` instead of `npx` for any package runner invocation (e.g. `bunx --bun playwright-core --version`).
- Checks, all run in CI (`.github/workflows/check.yml`): `bun --bun test`, `bun run lint` (oxlint), `bun check` (types, replaces `tsc`), `bun fmt --check` (formatter, replaces Prettier), `bun audit --prod`, and after `bun --bun run build`, `bun run size` (gzip budgets in `scripts/check-size.ts`; raise one only on purpose, in the commit that explains why). `.github/workflows/lint-workflows.yml` runs actionlint and zizmor on each change to `.github/`. `bun lint` is not in a stable Bun release yet (oven-sh/bun#46439 is after 1.4.4); when it ships, delete the `lint` script and the `oxlint` package, because `bun lint` reads `.oxlintrc.json` and a `lint` script would shadow it.
- React, React DOM and their types stay on `~19.2` (patches only). React 19.3 adds 8.7 kB gzip for `<ViewTransition />` and server APIs that this app does not use. The React advisories since 19.2 are in the `react-server-dom-*` packages (Server Components), which this app does not install; `react` and `react-dom` 19.2.9 have none. Move to 19.3 only for a fix or a feature the app needs, and check `bun audit` and the GitHub advisories for `react` and `react-dom` first.
- Dev-only pages (e.g. `dev/test.html`, the synthetic test-data generator) are routes in `scripts/dev.ts` only, never files in `public/`: `scripts/build.ts` copies `public/` into `dist/` as-is. Dev-only app code (`app/dev-data.ts`) returns early when `process.env.NODE_ENV === "production"`, which the build defines, so the bundler drops it; check with `grep` on `dist/`.
- `package.json` pins Bun in `packageManager` (`bun@1.4.4`). `oven/setup-bun` in CI reads it; the `oven/bun` tag in the `Dockerfile` repeats it. Change both in one commit.
- The Bun 1.4.4 dev server does not resolve a file created after it started ("Could not resolve"). Restart `bun --bun dev` after you add a file.
- `scripts/build.ts` adds a Content-Security-Policy to the built `index.html` only (the dev server needs a WebSocket for hot reload). It has `connect-src 'none'`, so the page cannot send an export anywhere. A feature that needs the network changes the policy on purpose. A new inline script or a style from another origin is blocked; check the browser console after the build.
- Releases: `bun pm version X.Y.Z` (bumps `package.json`, commits and tags `vX.Y.Z`; use `patch`, `minor` or `major` to count up), then `git push --follow-tags`. Only a `vX.Y.Z` tag deploys: `.github/workflows/deploy.yml` runs `check` once and checks that the tag matches `package.json` and is a commit on `main`; when both pass, the Pages build and the Docker push run in parallel. The image gets `X.Y.Z` and `X.Y`. Only the newest release also gets `latest` and the Pages deploy, so a fix to an older version or a pre-release (`1.3.0-rc.1`, its own tag only) does not replace the site. The `github-pages` environment allows the `main` branch and tags `v*`. A push to a branch deploys nothing; pull requests run `check`. Each job gets only the rights it needs, and every action is pinned to a commit with its version in a comment; `.github/dependabot.yml` updates the pins.
- The Docker image is BusyBox httpd (about 2 MB), with gzip copies of the JS, CSS and HTML made at build time. BusyBox knows few MIME types: a new file type in `dist/` needs a line in the `Dockerfile`'s `httpd.conf`, or it is sent with no `Content-Type`. Check with `curl -I`.
- Files that the app imports or that `index.html` links (`app/assets/`) are bundled and hashed. `public/` holds only files that must keep a fixed URL (the font, `llms.txt`).

## Code map

- `lib/stream.ts`: reads a JSON array from a byte stream one element at a time (a small depth and string scanner, then `JSON.parse` per element). Web APIs only, so the browser and `bun test` run the same code.
- `lib/upload.ts`: `loadExports` streams all picked files in parallel, keeps only `{ title, times }` per chat, yields to the browser about every 12 ms, and reports a partial result every 200 ms. A newer upload or a failed file cancels the rest.
- `lib/parse.ts`: export detection, per-chat summaries, and `dayFormatter`, which caches the local day of each 15-minute UTC block (exact for every UTC offset in use). It keeps the cache of the current zone only.
- `lib/aggregate.ts`: counts prompts per local day and per chat. A time zone change only re-buckets the stored times; it never parses the export again.
- `lib/calendar-geometry.ts`: `layoutCalendar` places every cell and label (pure, tested); `quartiles` and `level` pick a cell's shade level (1 to 4, by the quartiles of the active days); `fitScale` scales the calendar to its panel.
- `lib/stats.ts`: the figures above the calendar (total, active days, longest streak, busiest day, provider split), for all years or one. The README defines them; `test/oracle.test.ts` checks them with `jq`.
- `lib/providers.ts`: ChatGPT and Claude labels, the short export steps, the numbered `guide` for the welcome screen, Tailwind classes and the shade-class prefix (`ramp`). Use it; do not repeat provider colors in components. The shade colors are CSS variables (`--g1` to `--o4`) in `app/globals.css`, with a dark ramp that runs from dim to bright.
- `lib/layout.ts`: responsive layout decisions as pure, tested functions: the media queries, `foldPosture` (book, tent or one screen), the calendar orientation and the first year view. Extend those rather than re-deriving the logic inline in `app/page.tsx`.
- `lib/time-zones.ts`: the zones the picker offers and the ranked search (`buildIndex`, `searchZones`): city, zone, time name, abbreviation, offset, country and typos. `nearestFirst` lists UTC, then the zones nearest the computer's zone (no location prompt: the zone's own tzdata place). `lib/zone-data.ts` is generated by `scripts/gen-zones.ts` from tzdata `zone.tab` and `backward`; run it again with a new tzdata release. Country names come from `Intl.DisplayNames`. Chromium's `Intl.supportedValuesOf("timeZone")` has no "UTC" and uses legacy names (`Asia/Calcutta`), so `zoneList` adds UTC and the search resolves names with `resolvedOptions()`. The query table in `lib/time-zones.test.ts` is the judge of the search.
- `lib/file-drag.ts`: whether files are dragged over the page, and how many (browsers give no names before the drop). It refuses a drop outside a drop zone, so the browser never opens the file.
- `lib/sample.ts`: the seeded example year on the welcome screen. It is not real data.
- `lib/toast.ts`: a small toast store. `components/toaster.tsx` shows it in a native popover (top layer, `aria-live`), so no toast library is needed. Errors the user must see go through `toast("error", text)` too.
- `hooks/use-theme-toggle.ts`: the theme store. With no saved choice the page follows the computer; the button and the D key flip it, and a flip back to the computer's theme removes the saved choice.
- `hooks/use-upload.ts`: upload state for a drop zone or a file button. `hooks/use-fold-posture.ts`: the posture of a half-open foldable. `components/` holds the parts: `app-bar` (the top bar on every screen), `export-chips` (loaded exports in the bar with their chat counts; hover, focus or a tap shows the prompt count, the same rule as the cells, and every file name), `add-export` (the file button and the "How to export" popover; a mouse that rests on the help button opens it too, and a click then keeps it open), `export-panel` (the phone's panel under the bar), `page-drop` (once data is loaded, a file dragged anywhere shows one full-window target), `export-guide` (numbered export steps), `welcome` (the first screen), `mail-slot` (the welcome screen's drop zone, a post box; `mail-motion.ts` moves the file cards into it), `drop-zone` (the target inside `page-drop`), `loaded-files`, `fold-layout` (one pane per screen half of a half-open foldable), `time-zone-picker` (our own WAI-ARIA combobox: every library cost 30 to 62 kB gzip), `summary`, `year-tabs` (the view picker: a radio group; its pill can be dragged), `heat-legend` (its swatches are sized in em, so they grow with the text; the hollow "Outside the export" swatch has a stronger outline than the calendar's hollow days, which are 1.1:1 on the page), `calendar-heatmap`, `calendar-morph` (the year change motion: the morph, or the wave of `calendar-wave` between single years), `day-details` (a day's chats: a floating card, or a pane beside the calendar on a foldable), `site-links`, `theme-toggle`, `toaster`.
- Layout once an export is loaded: the top bar, then the figures, the year tabs and the calendar at full width. At `WIDE_BAR_QUERY` (76rem) and wider, the bar holds the export chips (with their chat counts), Add export and the time zone (a globe marks the field; its label is for screen readers); below it, the bar keeps the name and the links, and `export-panel` holds the rest. On a half-open foldable, `fold-layout` puts the bar, the figures, the tabs and the day pane on one screen half and the calendar on the other (book: side by side, the controls on the left unless swapped; tent: the calendar on top, the controls on the bottom half, which lies flat). The state that a fold or an unfold must keep (the view, the time zone, the picked day) lives in `app/page.tsx`, so a posture change keeps it. The page keeps the scrollbar's room (`scrollbar-gutter: stable` on `html`, which carries the page colour): a classic scrollbar that came and went with the view's height moved the centred page sideways. On wide windows the root font grows (112.5% from 1600 px, 125% from 1800 px, 150% from 2800 px), so a 1080p, 1440p or 4K screen at 1x keeps the proportions (at 1904 px the owner had to zoom to 125% to read the page); the calendar's scale limit grows with it.

## Data and tests

- A heatmap cell counts visible user prompts per local day (see "What a cell counts" in the README). `test/oracle.test.ts` runs the real upload path and checks it against `jq` in 3 time zones; it is the judge of every count. Keep both in step when the rule changes. Add a fixture case to `test/fixtures/` rather than a hand-made parse test; each rule needs a fixture node that only that rule excludes (the hidden text prompt and the shown `user_editable_context` node are there for that).
- `bun test` runs in UTC unless `TZ` is set, so a time zone bug passes locally. Run `TZ=America/New_York bun --bun test` and `TZ=Asia/Kolkata bun --bun test` for date code; CI runs all three. A test that needs a zone with daylight saving time sets `process.env.TZ` in `beforeAll` and restores it in `afterAll`.
- Motion code keeps the numbers it decides in small pure functions with tests (`startDelay`, `shape` and `placeBack` in `components/calendar-wave.test.ts`; `magnet`, `rubber` and `project` in `components/year-tabs.test.ts`); what needs a browser (the wave, the drag, keyboard focus, the calendar staying in place) is checked with Playwright scripts in the git-ignored lab (`.superpowers/keep/lab/year/app-check.ts`, `a11y-radio.ts`).
- Stream code is tested with a chunk boundary at every byte of each fixture. Keep that when you change `lib/stream.ts`.
- To prove a test can fail, break the code on purpose, run the test, and restore the code.
- The time zone combobox, the calendar's keyboard and tap details, the drop zone drag states and the toasts (Popover API) differ by browser. Test a change to them in Chromium, Firefox and WebKit (Playwright), and on a real Safari when you can. Headless Firefox reports no fine pointer, so it gets the phone layout.

## UI

- Import lucide icons from `"lucide-react"`, never from `"lucide-react/icons"`.
- Tailwind v4 scans only the `@source` paths in `app/globals.css`: `app/`, `components/`, `src/` and `lib/providers.ts`. A new file with class names outside those paths needs its own `@source` line, or its classes are silently missing.
- Colors come from tokens in `app/globals.css`, never from hard-coded values. The palette is Cobalt (picked in the palette lab; see the comments in `app/globals.css` for the measured contrast and color-blind numbers). Accent: `--color-accent` (focus rings, borders, icons; `ring-accent`, `text-accent`), `--color-accent-ink` (accent text and links, 4.5:1) and `--color-accent-fill` with `--color-accent-on` (a filled button and its text, 4.5:1; never `text-white`, so a palette may use a light button in dark mode). Providers: `--g-*` and `--o-*` (ramp levels 1 to 4, plus `-line`, `-wash`, `-ink`, `-dot` for the UI; `lib/providers.ts` uses them). Neutrals are Tailwind `zinc-*` only. Each token has a `.dark` value, so a component needs no `dark:` variant for these colors. The shadcn names (`text-muted-foreground`, `bg-primary`, ...) are not defined.
- All interactive elements (buttons, inputs) use `ring-2 ring-accent` for focus-visible rings.
- Ids are for citing a part of the page (in a review, a bug report, a CSS rule): every landmark, region and single control has one, in lower case words and dashes, named after its component (`app-bar`, `year-tab-2025`, `bar-time-zone`, `figure-streak`, `calendar-svg`). A component that can show twice takes an `id` prop and prefixes its ids with it. Repeated items (calendar days) use a data attribute (`[data-day="2025-03-14"]`), not an id. `components/ids.test.tsx` fails on a duplicate or an unreadable id on the loaded screen.
- Use the native element first: `ul`/`li` for lists, `h2`/`h3` for headings (a hidden one where a region has no visible title), `nav`, `section` with `aria-labelledby`, `fieldset`, `details`, the Popover API. A `role` only where no element fits (SVG cells, the combobox list), with a lint-disable comment that says why. Content that is only decoration and holds focusable parts gets `inert`, not only `aria-hidden`.
- Motion tokens (`app/globals.css`): `--ease-out`, `--ease-in-out`, `--ease-drawer`, the springs `--ease-spring` and `--ease-spring-bouncy` (CSS `linear()`, no library; their durations are `--dur-spring` and `--dur-spring-bouncy`), and `--dur-press`, `--dur-micro`, `--dur-ui`, `--dur-enter`. Use them; do not write a new curve or duration.
- The app font is Archivo, self-hosted from `public/fonts/`. Its `@font-face` is an inline `<style>` in `index.html`, not in `app/globals.css`: Bun puts every CSS `url()` asset under 128 kB into the CSS as base64 (oven-sh/bun#24599). Inline SVG `<text>` (the calendar heatmap) sets no `fontFamily`, so it inherits the body font. `body` uses `tabular-nums` so dates and counts line up.
- Heatmap motion: each cell carries its place in the date range as `--t` (0 to 1). While data streams in, cells fade over 180 ms, spread over 240 ms in date order. A time zone change runs a 700 ms wave (`sweep-a` and `sweep-b` alternate so each change restarts it). A change between two single years is a column wave (`components/calendar-wave.ts`, "Hit"): each week column dips, rises and slows into an invisible ceiling, squashes softly as its cells take their new shades, falls, lands and hops (300 ms a column, the columns spread over 600 ms in travel order, 900 ms in all; a vertical calendar waves across its 7 weekday columns). Its timings come from a lab study of real hits and the owner's feel checks, so they are constants in that file. Cells are keyed by date, so a new view has new cells: the wave keeps its own list of animations and the nodes it adds (ghosts, copies of the old split-day gradients) and stops from that list (`stopWave`), or a stale wave would remove a newer wave's gradient copies and split days would draw no fill (black in dark mode); a cell that a new change catches in the air settles from where it stood. A change to or from "All years" morphs (`components/calendar-morph.ts`): each day moves from its old place to its new one and takes its new shade (FLIP, transform and fill), in a wave by date over 180 ms on `--ease-spring`, and the month labels move with their weeks. From "All years" to one year, the years that leave stay where they were as one group and fade out (`--dur-ui`), and the drawing does not clip while the morph runs, because the year that stays rises from below the shorter new view; the page calls `prepareMorph(svg, dir)` before it changes the view (`dir` only between two single years); after a keyboard pick (`YearTabs` reports `key` for an arrow key or Space) it passes no calendar: the year changes at once and a running wave stops. The year picker is a native radio group in a fieldset (WAI-ARIA APG radio group): one tab stop at the picked year, the arrow keys pick the next or the previous year, Space the focused one; each year is a label around a visually hidden radio, named with its count ("2024 68 prompts"). A keyboard pick moves the pill at once (`data-instant`). The pill has a `zinc-500` ring, so the picked year differs from the row by 3:1 (WCAG 1.4.11); the focus ring of the picked year is drawn on the pill (`data-keys` keeps it in WebKit, which drops `:focus-visible` on arrow keys in a radio group); in forced colours the pill takes the system `Highlight`. The year tab pill lies over the labels and holds a copy of them, so a label takes the pill's colours exactly at its edge; it slides to the picked tab on `--ease-spring` (`--dur-spring`). It can be dragged (a magnet near each tab, a rubber band past the ends, a flick); while held it is accent glass (`.year-pill` in `app/globals.css`: the accent fill with a lit top and rim that stop above the labels, a glow from the pointer, a deeper shadow, a 1.04 lift on `--ease-spring-bouncy`; solid with reduced transparency or more contrast). The row clips only when its tabs do not fit (`data-fits`), so the pill and its shadow can pass its edge. Toasts rise in over 220 ms. While files are over the page drop target, an accent well follows the pointer (CSS variables written once a frame) and collapses into the drop point in 220 ms. The welcome screen's post box (`components/mail-motion.ts`, Web Animations): the flap opens as dragged files come near (up to 40 deg, written on the flap once a frame); a drop or a pick sends one card per file on an arc into the mouth, the card's edge pushes the flap open, the card slides in at its own pace, and the flap snaps shut (a spring cut where it first reaches shut, about 66 ms, no rebound). The read steers it: a done read speeds up the approach only; a slow read holds the last card partly in; a failed read slides it back out. The page keeps the welcome screen until the flap is shut (`onPosting`) and draws the loaded screen hidden meanwhile, so it shows at once. These timings were measured as one set from a frame-by-frame study of a real letter plate, so they are constants in that file, not `--dur-*` tokens. A theme change pauses all transitions until it is painted (`.theme-switching`), so every color changes at once; the theme button does not animate, because a late icon makes the switch look slow. The reduced-motion rule in `app/globals.css` makes all of it instant; keep that rule covering any new motion.
- Pass `fixedHeight` to `CalendarHeatmap` only where its panel has a fixed, short height (the tent posture's top half). A book pane scrolls like a phone. Elsewhere the page scrolls and the calendar fits its width (`maxScale` lets one narrow year grow); fitting to a height that comes from the calendar itself keeps the size of a short narrow moment (a resize, a rotation) for good.
- Every visit starts on "All years" (one year if the data has one); the view is not kept in the address, and an old `#all` or `#2025` is cleared on load. The calendar stays where it is on screen through a view change (`keepInPlace` in `components/calendar-morph.ts`, called by the page before every change, a keyboard one too): it records the calendar's top and holds the page at least as tall as it is scrolled; after the new view is drawn, and before the motion measures anything, it scrolls by how far the calendar moved, and what scrolling cannot make up (the figures above got shorter while the page is at its top) becomes padding above the calendar until the next change. Two things moved it before: one year after "All years" is about 400 px shorter (the browser pulled a scrolled page down), and the figures' captions can wrap onto a different number of lines for one year than for all of them. The hold ends once the content is tall enough again. Days outside the export are hollow (`lv-out`), so they do not read as days with no prompts. Each calendar has one tab stop; the arrow keys move between days.
- Foldables: the posture comes from the Viewport Segments API (`window.viewport.segments`, Chrome 138 and later; see `foldPosture`), because orientation cannot tell the arrangement: a Surface Duo shows its two screens side by side in a landscape window. Without that API, `device-posture: folded` with the orientation is the fallback (Device Posture, Chrome 132 and later). The pane tracks use `env(viewport-segment-*)` with a 50/50 fallback, so the gap sits exactly on the hinge. No popover, tooltip, toast or dialog may lie across the fold: place it inside the pane of its trigger (`.fold-pane`); the toasts keep to the right segment (`horizontal-viewport-segments: 2`). A Flip in Flex mode is a narrow tent: its top half shows the vertical calendar, scrolling; a tent of at least `MEDIUM_QUERY` (600 px) shows the year across. Test with CDP emulation in Playwright: `Emulation.setDevicePostureOverride` for the posture, and `Emulation.setDeviceMetricsOverride` with a `displayFeature` for the segments (in Chromium 158 `setDisplayFeaturesOverride` alone does not apply). Use the DevTools sizes: Galaxy Z Fold 6 cover 412x968, inner 744x860 with the fold at x 372; Surface Duo 1114x720 with a 34 px hinge at x 540. Check that no element sits on the hinge and that a fold and an unfold keep the view and the picked day, and test on a real device when you can.
- Size a part by the room it gets, not by the window: a fold pane is half the window, so use container queries (`@container` and `@xl:`) for parts that also sit in a pane (the figures, the export guide), not viewport breakpoints (`sm:`).
